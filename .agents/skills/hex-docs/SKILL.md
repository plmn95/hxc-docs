# Hex Composer documentation

Work in the documentation checkout, not the app's historical wiki.

Read [STYLE_GUIDE.md](../../../STYLE_GUIDE.md) for writing, section purpose,
UI terminology, and image presentation. For guides, captures, comparisons,
or downloadable patches, follow [AUTHORING.md](../../../AUTHORING.md).
Read [CONTRIBUTING.md](../../../CONTRIBUTING.md) when preparing a contribution
or checking the account-free editor.

Preserve useful existing content and unrelated changes. Base instructions
and captures on the identified app build. Keep unverified steps explicit;
do not treat source inspection or renderer output as a completed live UI
check. Keep published assets local and preserve capture provenance.
For figures that locate controls, use the shared annotation registry and
brand style described in AUTHORING.md. Preserve real screenshot pixels,
match numbered targets to visible explanations, and inspect desktop and
narrow layouts. Keep result previews clean when markers add no information.

Scale checks to the change using AUTHORING.md. Report what was tested and
what remains unverified. An ordinary prose correction does not require a
capture session or packaged app. Publishing is outside this authoring
workflow unless the user requests it.
